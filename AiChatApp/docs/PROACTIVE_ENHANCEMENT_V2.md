# AI 主动扫描增强方案 (V2 - Sentinel)

## 1. 设计背景
为了在不产生高额 Token 费用的前提下实现“项目自动监控与建议”，我们引入了“哨兵（Sentinel）”架构。

## 2. 哨兵架构设计 (Token-Saving Logic)

### 2.1 增量检测 (Git-Based Delta)
系统不再盲目扫描全量代码，而是利用 Git 的特性：
- **状态追踪**: `ProjectPulseService` 维护 `LastProcessedCommit`。
- **差异计算**: 仅通过 `git diff --stat` 获取两个版本间的变动摘要。
- **0 成本过滤**: 如果没有新提交或变动，分析流程将在本地终止，不消耗任何 AI 资源。

### 2.2 免费推理引擎 (OpenCode)
利用环境提供的 `opencode` 免费 CLI 工具：
- **强制指定**: 在 `AnalyzeProjectPulseAsync` 中明确调用 `provider: "opencode"`。
- **降级机制**: 如果 OpenCode 不可用，系统会根据配额自动降级，但优先使用免费资源。

## 3. 实现细节

### 3.1 脉搏分析流程
1. **获取 Hash**: 检查当前 HEAD。
2. **比较差异**: 若 Hash 变动，提取变动文件的统计信息。
3. **AI 评审**: 将 Diff Summary 发送给 Hyperion 哨兵。
4. **会话持久化**: 将建议存入名为 "Hyperion 任务洞察" 的持久化聊天中。
5. **实时分发**: 通过 SignalR 推送 UI 弹窗。

### 3.2 欢迎洞察
当用户登录并连接 WebSocket 时，系统会生成一份“断点续传”报告：
- **逻辑**: 汇总最近的 Git 提交历史和 Todo 状态。
- **交付**: 以“Hyperion 欢迎洞察”的形式呈现在前端。

## 4. 性能优化
- **节流处理**: `FileWatcherService` 增加了 2 秒的防抖处理，避免频繁修改导致的消息风暴。
- **后台执行**: 所有 AI 任务均在 `Task.Run` 中执行，不阻塞任何 HTTP 请求或 WebSocket 信号流。
